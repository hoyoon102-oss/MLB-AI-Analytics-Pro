# Version 4.6 — Career Development & Season Trends

## 1. 새 기능과 사용 순서

기존 4.5 기능과 다크 네이비 디자인을 유지하고 **커리어 분석** 메뉴를 추가했습니다.

1. `start.bat` 실행 후 선수를 선택합니다. 은퇴 선수는 전체 선수 이름 검색을 사용하세요.
2. **커리어 분석 → 타격/투구 선택 → 전체 커리어 불러오기**를 누릅니다. 현재 선택 시즌에 기록이 없어도 전체 커리어를 조회할 수 있습니다.
3. 데뷔 연도, 범주별 최근 출전 시즌·출전 시즌 수, 공식 통산 경기·PA/IP와 통산 기록을 확인합니다.
4. 기간과 지표를 고르면 실제 기록·누락 시즌·잠정 시즌·수상 마커, 전후 변화량, 규칙 기반 개선/하락과 최고 시즌 후보를 볼 수 있습니다.
5. 필요할 때만 **추가 자료 불러오기**로 연도별 MLB 평균과 2015년 이후 Statcast 시즌 요약을 조회합니다.
6. 커리어 구간 및 직접 선택한 시즌의 합계 비율을 확인하고, 로컬 AI를 켜서 보고서를 생성하거나 질문할 수 있습니다.
7. **선수 비교 → 두 선수 커리어 추세 비교**에서 달력 연도/데뷔 이후 연차를 비교합니다. 기존 유사 선수 결과의 **커리어 보기**도 연결했습니다.

요약은 전체 커리어이고 차트·변화·최고 시즌 후보는 선택한 표시 기간 기준입니다. 한 지표로 객관적인 종합 최고 시즌을 선언하지 않습니다.

## 2. 데이터 출처와 커리어 집계

기본 출처는 MLB Stats API입니다.

```text
/api/v1/people/{MLBAM ID}/stats
  ?stats=yearByYear,career
  &group=hitting 또는 pitching
  &sportIds=1
  &gameType=R
```

실제 응답에서 `yearByYear`와 `career`가 별도 통계 그룹으로 반환되는 것을 확인했습니다. MLB ID·유형·시즌·정규시즌·스포츠를 검사하며 타격/투구를 분리합니다.

- 시즌 합계와 개별 팀 기록이 같이 있으면 **공식 시즌 합계만 선택**합니다. 둘을 더하지 않습니다.
- 공식 합계가 없으면 서로 다른 팀의 원자료 개수를 합산하고 비율을 다시 계산합니다. 팀 중복이나 모호한 합계는 오류 상태로 남깁니다.
- 중단 경기에서 같은 선수가 두 팀 소속으로 출전할 수 있으므로 합계가 없는 이적 시즌의 경기 수는 무조건 더하지 않고 N/A로 둡니다. 공식 통산 경기 수가 있으면 그 값을 사용합니다.
- 통산 비율은 공식 `career` 값을 우선 사용합니다. 공식 통산값이 없을 때만 검증 가능한 시즌 원자료를 합칩니다. 시즌 AVG·OPS·ERA의 단순 평균은 사용하지 않습니다.
- 투구 IP는 아웃으로 변환해 합칩니다. `6.1 + 3.2 = 10.0`이며 소수 이닝 덧셈을 하지 않습니다.
- 미반환 시즌과 검증 실패 시즌을 별도로 기록합니다. 연도순으로 정렬하고 공백을 None으로 보존합니다. 확인된 데뷔가 해당 범주의 첫 기록보다 이르면 그 앞의 공백도 화면에 표시합니다.
- 범주별 최근 출전 시즌 이후의 기록이 없는 연도를 미래 기록으로 생성하지 않습니다.

리그 평균은 기존 `fetch_league_average`를 재사용합니다. Statcast는 4.5의 시즌 Custom Leaderboard를 재사용하며 전체 선수의 투구 원자료를 받지 않습니다. 기존 수상 정규화·조회 기능도 그대로 사용합니다. 발표 날짜가 다음 해여도 확인된 `season` 필드로 연결합니다.

## 3. 변화·최고 시즌·평활 방법

### 전후 변화

실제로 기록이 확인된 다음 출전 시즌과 비교합니다. `다음 값−이전 값`, 이전/다음 PA 또는 IP, 실제 연도 간격을 표시합니다. 공백이 2년이면 1년 변화라고 표현하지 않습니다.

ERA·WHIP·BB/9는 낮아지는 방향을, 타자 OPS·OBP·ISO 등은 높아지는 방향을 선호 방향으로 표시합니다. 타자 K%와 투수 BB%는 낮을수록 선호됩니다. HR·RBI·SO·IP는 출장량과 함께 해석합니다.

상대 변화율은 양수인 이전 값에 대해 의미 있는 비율/누적 지표만 제공합니다. 퍼센트 지표의 차이는 pp이며, %·지수·IP 또는 0 이하 기준값에는 상대 변화율을 붙이지 않습니다.

### 표본과 최고 시즌

- 타격 비율: **300 PA 이상**, 계산에 필요한 유효 분모.
- 투구 비율: **100 IP 이상**. K-BB%는 추가로 **300 BF 이상**.
- 이는 앱이 선택한 설명용 기준이며 공식 MLB 타이틀 자격과 다릅니다.
- 미완료 시즌은 최고·변화 탐지 후보에서 제외합니다. 최고 후보가 동률이면 모두 표시합니다.
- 지원하지 않는 OPS+·wRC+·ERA+는 기존처럼 N/A입니다. FIP·wOBA는 기존 검증 상수의 시즌 범위를 유지합니다.
- 최고 후보에는 출전량·해당 시즌 리그 문맥·함께 볼 지표와 확인된 수상을 표시합니다. 확인되지 않은 값은 N/A입니다.

### 통계적 개선/하락과 브레이크아웃

큰 변화 후보는 표본 기준을 충족한 완료 시즌 사이에서 **OPS 절대 변화 0.100 이상** 또는 **ERA 절대 변화 1.00 이상**일 때 표시합니다. ERA 상승은 하락 방향입니다.

이것은 **설명용 크기 규칙**이며 통계적 유의성 검정, 재능 변화 또는 원인 판정이 아닙니다. 작은 변화에 과장된 의미를 붙이지 않습니다. 검증 실패 시즌을 가로지르는 탐지는 제외합니다.

브레이크아웃 후보에는 추가로 다음을 요구합니다.

- 이전 **2~3개 표본 자격 시즌**의 검증된 리그 문맥.
- 타자 `OPS / 리그 OPS`, 투수 `리그 ERA / ERA` 비율. 두 경우 모두 큰 값이 선호 방향입니다.
- 이전 자격 시즌의 비율 평균보다 **0.15 이상** 높고 현재 비율이 **1.0 이상**인 완료 시즌.
- 이전 비율 평균은 후보 판정의 설명용 기준이며 통산 비율 통계가 아닙니다.

이 비율은 구장 미보정 비교이므로 **OPS+·ERA+라고 표시하지 않습니다**. HR·RBI 개수만으로 후보를 만들지 않으며, 리그 평균·이전 시즌·표본이 부족하면 결과 없음으로 안내합니다. 부상·코칭·메커니즘·노화·동기 같은 원인은 추정하지 않습니다.

### 구간 합계와 평활

기본 구간은 실제 출전 순서 1~3, 4~6, 7~10, 11번째 이후입니다. 공식 MLB 구간이나 신체 발달 단계가 아닙니다. 사용자가 별도 시즌 묶음을 선택할 수도 있습니다. 비율은 선택 시즌의 원자료 합계로 다시 계산합니다.

평활선은 **3개 연속 달력 시즌**의 원자료를 합쳐 다시 계산합니다. AVG·OBP·SLG·OPS·ISO·BB%·K%, ERA·WHIP·K/9·BB/9·K-BB%에 지원합니다. FIP·wOBA·Statcast 등 지원하지 않는 평활은 빈 값으로 둡니다. 공백을 건너뛰거나 미래로 연장하지 않습니다.

## 4. 비교·AI·시즌 상태

두 선수 비교의 연차는 확인된 MLB 데뷔부터의 **경과 연도**입니다. 출전 공백도 포함하며, 데뷔 정보가 없으면 해당 범주의 첫 기록을 기준으로 한다고 안내합니다. 커리어 구간의 ‘출전 순서’와는 구분합니다.

유사 선수의 과거 커리어를 열거나 기존 비교 화면에서 확인할 수 있지만, 그 선수의 이후 성적이 대상 선수의 미래라고 주장하지 않습니다. 투수/타자 지표는 분리합니다.

현재 시즌 종료 여부는 MLB 시즌 일정의 `regularSeasonEndDate`로 판단합니다. 일정이 없으면 과거 연도만 완료로 간주하고 현재 연도는 보수적으로 잠정 처리합니다. 1994·1995·2020년은 알려진 단축 시즌으로 표시하며 역사적 일정 형식이 모두 같다고 가정하지 않습니다. 근거: [1994 시즌 중단](https://www.mlb.com/postseason/history/1994), [1995 시즌 회고](https://www.mlb.com/news/mlb-1995-year-in-review), [2020 시즌 발표](https://www.mlb.com/news/mlb-announces-2020-regular-season).

AI에는 선택 기간·직접 계산한 변화량·규칙 후보·선택 기준 최고 시즌·검증된 수상·리그 출처만 전달합니다. 보고서는 개요, 개선, 하락/변동, 최고 시즌, 리그 대비, 수상, 한계, 종합 해석 순서입니다. 실제 통계와 AI 해석을 구분하며 버튼·질문 전송 때만 생성합니다. 수상 문맥은 최대 100개를 넣고 잘림 여부와 전체 요약을 명시합니다.

## 5. 파일과 성능

신규:

- `services/career_stats_service.py`: 전체 커리어, 시즌별 상태, 선택적 리그/Statcast 문맥
- `analytics/career_trends.py`: 합계 비율, 전후 변화, 표본, 최고 시즌, 큰 변화/브레이크아웃, 평활, AI 요약
- `components/career_charts.py`, `components/career_ui.py`
- `tests/test_career_trends.py`, `tests/test_career_ui.py`
- `scripts/check_career_live.py`, `docs/career-live-evidence.json`, 이 보고서

수정: `components/dashboard.py`, `components/ui_components.py`, `components/rankings_ui.py`, 양쪽 번역 JSON, `tests/__init__.py`, `README.md`.

커리어는 선수 ID·범주·조회일별 15분 캐시, 최대 64개입니다. 시즌 일정은 1시간 저장합니다. 리그·Statcast는 기존 캐시를 재사용하고 명시적 추가 조회 때만 받습니다. 프로필·수상도 기존 서비스를 재사용합니다. 새 의존성·유료 API·예측 모델은 추가하지 않았습니다.

## 6. 검증 결과

전체 자동 테스트 **200개 통과, 실패 0개**입니다. 기존 183개와 신규 17개를 실행했습니다. `v46-test-results.log`에서 확인할 수 있습니다.

새 테스트는 시즌 정렬·공백·이적 합계·중복 거절·선수/범주 구분·올바른 합계 비율·아웃·0 분모·음수 K-BB%·변화 방향·상대 변화율 제한·표본·동률 최고 시즌·평활·브레이크아웃 조건·연차·수상 시즌·AI 문맥·언어·짧은 커리어·명시적 로딩을 포함합니다.

실제 API 확인:

| 선수 | 확인한 범주/범위 |
|---|---|
| 오타니 | 타격 2018~2026, 투구 2018~2026의 공백 포함 기록 |
| 저지 | 타격 2016~2026 |
| 커쇼 | 투구 2008~2025 |
| 스쿠벌 | 투구 2020~2026 |
| 스킨스 | 투구 2024~2026, 짧은 기록 |
| 푸홀스 | 타격 2001~2022, 은퇴·2021 이적 합계 |

각 사례에서 시즌별 안타 또는 아웃의 합계가 공식 통산 합계와 일치했습니다. 2021·2022·2024년 MLB 리그 평균도 별도로 확인했습니다. 실제 결과·조회 시각·출처는 `docs/career-live-evidence.json`에 저장했습니다.

Streamlit 서버 시작·health와 실제 `start.bat`의 시작/검증 프로세스 종료 모두 통과했습니다. 이번에 실제 Ollama 문장 생성과 Playwright 전체 시각 검증은 추가 실행하지 않았습니다. 로딩된 새 화면은 AppTest로, AI 문맥·언어·호출은 mock으로 확인했습니다.

기존 테스트가 실제 즐겨찾기 존재 여부에 영향을 받는 문제를 발견해 테스트 프로세스 전체를 임시 데이터 폴더로 격리했습니다. 기존 즐겨찾기·설정은 작업 전후 SHA-256 해시가 동일합니다. 기존 계산 모듈과 테마도 백업과 동일합니다.

## 7. 알려진 제한

미제공 역사 자료와 확인 실패는 N/A로 보존합니다. 공식 구장 보정 지표나 미검증 시즌 상수는 만들지 않습니다. Statcast는 2015년 이후 제공되는 시즌 요약만 지원합니다. 앱의 고정 표본 기준 때문에 단축 시즌·신인·구원투수의 최고/변화 후보가 없을 수 있습니다. 모든 단축 시즌을 완전히 분류한 것은 아닙니다. 기록 차이가 재능 변화나 인과관계를 증명하지 않으며, AI 해석은 원자료와 대조해야 합니다.
